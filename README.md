# Feberis Pro Companion App

A Flipper Zero application for controlling the Feberis Pro ESP32-C5 Wi-Fi
wardriver, recording observations to microSD, and exporting WiGLE-compatible CSV.

The application supports **Feberis Pro firmware 0.3.0 with FBR1 revision 2**.
Firmware 0.2.0 is supported without extended memory diagnostics. Firmware 0.1.0
requires the earlier companion application.

Firmware project: [bpmcircuits/feberis_pro_wardriver](https://github.com/bpmcircuits/feberis_pro_wardriver).

## Features

- SMART, FULL, and UNIQUE recording modes, with both-band, 2.4 GHz, and 5 GHz schedules.
- Configuration read from the ESP, including an explicit active probing setting.
- Durable observation journal, acknowledgements after SD synchronization, and session recovery.
- Streaming exports: observations, final AP aggregates, WiGLE CSV, statistics, and metadata.
- Paginated network browser, full AP details, GPS information, and separate SRAM/PSRAM diagnostics.
- Native Flipper menus, pause/resume, session browsing, and explicit recovery controls.

## Install

Build the application with `ufbt` as described below. Copy the resulting
`dist/feberis_pro.fap` to `/ext/apps/GPIO/` using qFlipper, then open
**Apps → GPIO → Feberis Pro**. Generated binaries are not committed to Git.

The verified build uses **Flipper SDK 1.4.3, f7, API 87.1**. If your Flipper
firmware uses a different API, rebuild with its matching SDK.

## Connect the hardware

UART uses **3.3 V logic, 8N1, no RTS/CTS**, initially at **115200 baud**.

| Feberis Pro / ESP32-C5 | Flipper Zero |
| --- | --- |
| UART0 TX, GPIO11 | RX of the selected UART |
| UART0 RX, GPIO12 | TX of the selected UART |
| GND | GND |

Select **USART** or **LPUART** in **Menu → Settings → UART** to match your wiring.
GPIO11/12 are ESP32 GPIO numbers, not Flipper connector pin numbers. Power the
Feberis separately; the application does not enable the Flipper's 5 V output.

GPS stays connected to the ESP: UART1 at 115200 baud, GPIO14 RX / GPIO13 TX.
Those ESP pins share the native USB function. Keep UART0 available when flashing
the Feberis firmware.

## First session

1. Select the UART and press **Connect**. Wait for the device checks and confirmed IDLE.
2. Review **Settings**, which displays the configuration reported by the ESP.
   Firmware defaults are SMART, BOTH, and passive scanning. **Active probing → ON (probe)**
   explicitly enables active scans.
3. Press **Start**. The application creates a session journal before sending START_SCAN.
4. Press **Stop** to drain pending observations, retrieve final AP aggregates, and export the session.

**Unique AP** comes from device statistics. **SD saved** counts durably journaled
observations, including observations without a GPS fix.

Sessions are stored under:

```text
/ext/apps_data/wardriving/sessions/session_YYYYMMDD_HHMMSS_NNNN/
    events.journal
    metadata.json
    observations.csv
    access_points.csv
    wigle.csv
    stats.json
```

After an error, **Retry** recovers and archives the existing session.
**Menu → Recover and resume** explicitly resumes the same session if the ESP is
still running it and retains its data. An ESP restart never automatically starts scanning.

## Build and test

Install [uFBT](https://github.com/flipperdevices/flipperzero-ufbt), then run:

```sh
git clone https://github.com/bpmcircuits/feberis_pro_companion_app.git
cd feberis_pro_companion_app
ufbt
./tests/run.sh
```

The output is `dist/feberis_pro.fap`. Host tests require a C compiler with
AddressSanitizer/UndefinedBehaviorSanitizer support, a POSIX shell, and Python 3.
They use temporary files and simulated UART/storage failures. Python independently
validates the actual CSV and JSON generated by the C exporter.
